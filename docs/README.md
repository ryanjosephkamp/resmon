# `docs/` — the published site, and the documents it publishes

Two things live here, and knowing which is which is the whole of this file.

**Markdown sources, edited by hand.** These are the files the repository itself links to by
path, so they stay where they are:

- `*.md` — the reference documents: `source-landscape.md`, `backup.md`,
  `local-api-security.md`, `adding-a-source.md` and the rest.
- `_posts/*.md` — the 27 release-update posts, named `YYYY-MM-DD-<slug>.md`.
- `api-contract/*.md` and `api-contract/openapi.json` — **generated and guarded.**
  `implementation_scripts/api_contract.py` writes `openapi.json` and `http.md` from the running
  FastAPI application, and `verification_scripts/test_api_contract.py` regenerates both and
  fails on any difference. Never edit them by hand; regenerate with
  `python -m implementation_scripts.api_contract --write` from `resmon_scripts/`.

**Everything else here is build output** — `index.html`, the per-page directories, `feed.xml`,
`static/`, `screenshots/`, `404.html`, `.nojekyll`. It is generated by the Astro site in
[`../site/`](../site/) and committed, because GitHub Pages publishes this folder directly
rather than building anything. Do not edit it; edit the site and rebuild.

```bash
cd site
npm install          # first time only
npm run build        # astro build, then copies the output in here
npm run verify       # checks the result against the captured live site
```

`site/scripts/sync-docs.mjs` is what copies the output in. It deletes the previous build and
leaves the Markdown sources above untouched; its `PROTECTED` list is the authority on which
files are which.

## Publishing

GitHub Pages serves this folder at <https://ryanjosephkamp.github.io/resmon/>:
**Settings → Pages → Source = "Deploy from a branch", Branch = `main`, Folder = `/docs`.**
There is no workflow; a push to `main` that changes this folder republishes it within about a
minute.

`.nojekyll` is what stops GitHub running Jekyll over the built files. Without it, nothing under
`_posts/` would be served and the build output would be rebuilt as if it were a Jekyll source
tree. It is written by every build.

## Writing an update post

Create `_posts/YYYY-MM-DD-resmon-update-<N>.md`:

```yaml
---
layout: post
title: "resmon Update <N> — <Month> <D>, <YYYY>"
date: YYYY-MM-DD HH:MM:SS -0400
categories: [updates]
---
```

Then the body, starting with a single `# Update <N> — <what it was about>` heading. That
heading becomes the page's title and the feed entry's summary; the front-matter `title` becomes
the feed entry's `<title>` and the row label in the app's Blog tab.

Two things about the front matter are load-bearing:

- **`date` sets the URL, and it is read in UTC.** The post is published at
  `/:year/:month/:day/:slug/` taken from the UTC instant, so `date: 2026-09-06 21:00:00 -0400`
  publishes under `/2026/09/07/`. Two of the existing posts already do this. The `YYYY-MM-DD`
  in the file name is convention and the slug after it is the URL's last segment, but the day
  in the URL comes from `date`.
- **`layout: post` is inert** and kept only so the files still read as they were written. The
  site ignores it.

Rebuild and commit `docs/` in the same change as the post. The app's
**About resmon → Blog** tab reads `/feed.xml` on every open; the feed carries the 10 most
recent posts, and `site/src/pages/feed.xml.ts` says why it is 10 and what the app reads from it.
